# Project Scope

**Project:** RetailPulse - E-Commerce Revenue, Customer Behaviour & Retention Analytics

**Selected dataset:** Brazilian E-Commerce Public Dataset by Olist.

The selected Olist dataset does not contain true seller cost or profit data, so profitability metrics are intentionally excluded.

Freight value represents freight charged in the transaction and must not be interpreted as seller shipping cost.

The project will not claim churn or causal effects from these observational transaction data.

## Primary Analysis Areas

1. Revenue Analytics
2. Product Analytics
3. Customer Analytics
4. Regional Analytics
5. Repeat Purchase Analytics
6. Retention / Cohort Analytics, if supported by the inspected data

## Planned KPIs

### Sales

- Total Revenue
- Total Orders
- Total Quantity Sold
- Average Order Value
- Monthly Revenue
- Month-over-Month Growth

### Customers

- Total Customers
- New Customers
- Repeat Customers
- Repeat Purchase Rate
- Revenue per Customer
- Purchase Frequency

### Retention

- Customer Retention
- Cohort Retention
- Repeat Purchase Trend

> These remain proposed measures, not findings. The source files have now received an initial inspection; exact definitions must still be documented before analysis. Profitability KPIs are excluded because the dataset has no true seller cost or profit fields. Churn is not a project claim.

## Project Quality Rules

1. Never fabricate business findings.
2. Never fabricate dataset values.
3. Validate data before analysis.
4. Define KPIs before calculating them.
5. Every chart must answer a business question.
6. Prefer business relevance over visual complexity.
7. Correlation must not be presented as causation.
8. Document assumptions and limitations.
9. Validate Power BI totals against SQL/source data.
10. Analysis must be understandable enough to explain in interviews.
11. Avoid unnecessary tools and overengineering.
12. Keep the project reproducible.
